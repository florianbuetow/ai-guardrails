# Product Specs

Product specs describe user-facing behavior: who needs it, what it does, and how to
tell that it works. This catalog lists every spec with its status.

## Status

- **Draft**: under discussion.
- **Accepted**: agreed and ready to build.
- **Shipped**: implemented and matching the current product.
- **Retired**: no longer part of the product.

## Writing a spec

Create `product-specs/<feature>.md`, for example `new-user-onboarding.md`, with these
sections:

- **Problem**: who has it and why it matters.
- **Behavior**: what the user can do, step by step.
- **Acceptance criteria**: observable checks that prove the behavior works.
- **Out of scope**: what the spec deliberately leaves out.

Add its row to the catalog in the same commit.
