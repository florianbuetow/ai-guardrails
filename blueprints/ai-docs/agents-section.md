## Documentation

The repository is the system of record. Agents see only what is written here: a
decision, rule, or plan that lives in a chat or in someone's head does not exist for
them. This section maps that knowledge. Read it first, then open only the documents
your task needs.

### Layout

| Path | Purpose | Read it when | Update it when |
|------|---------|--------------|----------------|
| [ARCHITECTURE.md](ARCHITECTURE.md) | Map of the code: modules, layers, invariants | You change code structure or dependencies | A module, layer, boundary, or invariant changes |
| [docs/design-docs/index.md](docs/design-docs/index.md) | Catalog of design docs with their verification status | You design or change how something works | You add, verify, or supersede a design doc |
| [docs/design-docs/core-beliefs.md](docs/design-docs/core-beliefs.md) | Agent-first operating principles | You start any task | The team changes how it works |
| [docs/exec-plans/active/](docs/exec-plans/active/) | Execution plans in progress, one file per plan | You resume multi-step work | At every stopping point of that work |
| [docs/exec-plans/completed/](docs/exec-plans/completed/) | Finished plans with their outcomes | You need to know why something was built as it is | A plan is done: move it here from `active/` |
| [docs/exec-plans/tech-debt-tracker.md](docs/exec-plans/tech-debt-tracker.md) | Known technical debt | You plan cleanup or touch affected code | You find debt you do not fix now, or pay it down |
| [docs/generated/index.md](docs/generated/index.md) | Documents generated by tools, such as schema dumps | You need exact facts about generated artifacts | Never by hand: regenerate them from their source |

| [docs/SECURITY.md](docs/SECURITY.md) | Security rules and threat model | You handle input, secrets, authentication, or dependencies | A rule or threat changes |

### Working with the documentation

- Update documents in the same commit as the change that makes them stale. A document
  that disagrees with the code is a bug: fix whichever one is wrong.
- Small changes need only a short plan in the task or pull request. Complex work gets
  an execution plan in `docs/exec-plans/active/`, written as `docs/PLANS.md` describes,
  and moves to `docs/exec-plans/completed/` when it is done.
- List every new design doc, product spec, generated document, and reference file in
  its folder's `index.md` in the same commit.
- Never edit files in `docs/generated/` by hand.
- Record debt you do not fix now in `docs/exec-plans/tech-debt-tracker.md`.
- Write down what reviews, bugs, and discussions teach. When a rule matters enough to
  fail the build, enforce it with a test or linter instead of prose.
- Link to the one place a fact is recorded instead of repeating it.
- Keep this map current when you add, rename, or remove a document.
